# 毎朝AI/ITダイジェスト — 2026年8月3日(月)

今日はモデル・開発ツール・エージェント基盤の3領域から、DeepSeek V4-Flash 0731の正式リリース、Codex CLI v0.146.0のプラグイン/リモートCode Mode対応、Y Combinatorが社内利用のマルチエージェント基盤「QM」をOSS公開した件を取り上げる。

## 1. DeepSeek、V4-Flashをプレビューから正式版「V4-Flash-0731」へ昇格 — Terminal-Bench 2.1で82.7点

**情報源・日付**: MarkTechPost (2026-07-31)、DeepSeek API Docs Change Log、TechNode (2026-07-31)、Fireworks AI/OpenRouter/DeepInfraの各モデルページ

**何が新しいか**: DeepSeekが4月に公開していたプレビュー版「V4-Flash-preview」を、7/31付で正式なパブリックベータAPI「DeepSeek-V4-Flash-0731」として昇格させた。アーキテクチャ・パラメータ数は据え置きで、エージェント/コーディング用途向けに再事後学習(post-training)のみをやり直したモデル。

**技術的なポイント**: 284Bパラメータ・アクティブ13BのMoE構成、コンテキスト長1Mトークンはプレビュー版から変更なし。価格もキャッシュミス時$0.14/M入力・$0.28/M出力・キャッシュヒット時$0.0028/Mと据え置き。新たにOpenAIのResponses API形式をネイティブサポートし、Codex系ハーネスからアダプター無しで呼び出せるようになった。ベンチマークはTerminal-Bench 2.1で82.7点を報告(ただし4月版はTerminal-Bench 2.0での評価のため単純比較はできない点に注意)。呼び出しは既存の`deepseek-v4-flash`エンドポイントのまま自動的に新バージョンへ切り替わる。

**なぜ重要か**: 低価格帯(GPT/Claude系の数分の一)でエージェント/コーディング用途に強いオープンウェイト系モデルの選択肢が着実に強化されている。自前のエージェント基盤やコスト制約のあるPoCでモデルを選定する際、こうした低コストかつResponses API互換のモデルはFDE的な検証・提案業務で実務的な比較対象になる。

**リンク**: https://www.marktechpost.com/2026/07/31/deepseek-upgrades-deepseek-v4-flash-0731-with-major-agentic-and-coding-gains/ / https://api-docs.deepseek.com/updates/ / https://openrouter.ai/deepseek/deepseek-v4-flash-0731

## 2. OpenAI Codex CLI v0.146.0 — セッション命名、Agent Pluginsマニフェスト、リモートCode Modeホスト対応

**情報源・日付**: GitHub `openai/codex` Releases (v0.146.0、2026-07-29)

**何が新しいか**: Codex CLIの最新安定版v0.146.0で、複数の並行会話をセッションに名前を付けて管理できる機能や、スレッドのピン留めが追加された。プラグイン配布の仕組みが正式化され、Amazon Bedrockや(サードパーティの)プラグインマーケットプレイス連携も強化されている。

**技術的なポイント**: 新たに「Agent Pluginsマニフェスト」でワークスペーススコープのプラグインを公開できるようになり、WebSocket経由でリモートのCode Modeホストに接続する機能も追加された。加えてシステムプロキシ設定の統一対応、MCPコネクション管理の強化、ターミナルのレンダリング・応答性改善など運用面の細かな改善も多数含まれる。次期v0.147.0系のアルファ版も並行して公開されている。

**なぜ重要か**: セッション/プラグイン管理やリモートホスト接続の強化は、複数プロジェクト・複数クライアントを横断してコーディングエージェントを運用する場面で直結する機能。MCP接続の安定性改善も含め、エージェントCLIを実務ツールとして使い込む上での実装パターンとして押さえておく価値がある。

**リンク**: https://github.com/openai/codex/releases

## 3. Y Combinator、社内で使う「マルチプレイヤー」エージェント基盤「QM」をMITライセンスでOSS公開

**情報源・日付**: GitHub `yc-software/qm` (2026年7月末公開)、Y Combinator公式X投稿

**何が新しいか**: YCが経理・法務・イベント運営・エンジニアリングなど社内の複数部門で実際に使っているマルチエージェント基盤「QM」(Quartermaster)をMITライセンスでオープンソース公開した。QM自体の開発にもQMを使っているという。個人ごと・部屋(チャンネル)ごとにスコープされたメモリ・ファイル・鍵管理ビュー・権限・cronジョブ・サンドボックスを持つ設計。

**技術的なポイント**: TypeScript/Node.js製で、HTTPはFastify、SlackはBolt、UIはVite+Litで構築。バックエンドはPostgreSQLでセッション・メモリ・キューを保持。Pi・OpenCode・Codex・Claude Codeなど複数のエージェントハーネスをバックエンドとして選べるクラウドファースト設計で、SlackとWebアプリの両方から同一のIDでアクセスできる。セキュリティ面では「Strict」「Auto」「Dangerous」の3段階のポスチャーを提供。GitHub上で7.0kスター・736フォーク(確認時点)。

**なぜ重要か**: 単一エージェントのCLI/IDE統合が主流だった中、「会社全体で複数人・複数部門が共有のエージェント基盤を使う」運用パターンをOSSかつ実運用実績付きで示した点が注目に値する。権限分離・監査・マルチテナント設計は、エージェントを顧客企業に導入するFDE的な役割で必ず直面する課題であり、実装の参考例として一読の価値がある。

**リンク**: https://github.com/yc-software/qm
