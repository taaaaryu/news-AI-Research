## 1. Anthropic、Claude Opus 5を正式発表 — Fable 5級の性能を約半額のコストで

**情報源:** [TechCrunch](https://techcrunch.com/2026/07/24/anthropic-launches-opus-5/)、[Bloomberg](https://www.bloomberg.com/news/articles/2026-07-24/anthropic-unveils-more-cost-efficient-model-for-everyday-tasks)、[Axios](https://www.axios.com/2026/07/24/anthropic-releases-new-model-opus-5)、[9to5Mac](https://9to5mac.com/2026/07/24/anthropic-upgrades-claude-with-new-opus-5-model-details-here/)（いずれも2026年7月24日）、加えて[Claude Code公式changelog](https://code.claude.com/docs/en/changelog)がモデルID`claude-opus-5`の実在を裏付け

**何が新しいか:**
Anthropicが2026年7月24日、新モデルClaude Opus 5を発表。現行最上位モデルFable 5に近い性能を、多くのタスクで約半額のコストで実現するとしている。1Mトークンのコンテキストウィンドウ、最大128Kトークンの出力、拡張思考(extended thinking)がデフォルト有効という構成。

**技術的なポイント:**
- SWE-bench Pro（実際のGitHub issueをlive repositoryに適用し、プロジェクト自身のテストを通すかで評価するベンチマーク）で79.2%を記録したと報じられている（codersera等の二次情報源、Anthropic公式ベンチマークカードでの直接確認はできていない）。前モデルOpus 4.8の69.2%から大幅に向上し、Mythos 5(80.3%)・Fable 5(80.0%)にわずかに次ぐ3位相当。
- 価格は入力$5/出力$25 per Mトークン（TechCrunch報道の標準・thinkingモード）。一方、Anthropic公式のClaude Code changelogでは「fast modeで$10/$50 per Mトークン」と明記されており、モードによって価格帯が異なる点に注意。
- Claude Maxのデフォルトモデル、Claude Proの最上位モデルとして提供開始。リクエスト単位で推論に割く計算量を調整できるeffort設定を搭載（段階数は情報源により記載が「5段階」「low/medium/high」など揺れがあり未確認）。

**なぜ重要か:**
コスト効率の良いフラッグシップ級モデルが増えるほど、エージェント基盤のモデル選定でトレードオフ（性能・速度・価格）を定量的に説明する仕事の重要性が増す。FDE的な役割では、顧客ごとの用途に応じてこうした複数モデル・複数モードの使い分けを提案できることが差別化要因になる。

**リンク:** https://techcrunch.com/2026/07/24/anthropic-launches-opus-5/

## 2. Claude Code 2.1.219 — sandboxネットワーク制御・DirectoryAddedフック・MCPエラー可視化を追加

**情報源:** [Claude Code公式changelog](https://code.claude.com/docs/en/changelog)（2026年7月24日付、直接WebFetchで確認）

**何が新しいか:**
Claude Code 2.1.219で、Claude Opus 5への対応に加えて、サンドボックス実行のセキュリティ強化とMCPサーバーの障害可視化に関わる複数の設定が追加された。

**技術的なポイント:**
- `sandbox.network.strictAllowlist`設定を追加。ホワイトリストに登録されていないホストへの通信を、ユーザーへの確認プロンプトなしで自動的に拒否できるようになった。
- `DirectoryAdded`フックを追加。`/add-dir`コマンドやSDKの`register_repo_root`制御リクエストでセッション中盤に新しい作業ディレクトリが登録された際に発火する。
- headless実行時のstream-json initイベントに`mcp_server_errors`フィールドを追加。`--mcp-config`の設定検証で読み込みをスキップされたMCPサーバーエントリを一覧表示し、ターミナル実行時は起動時警告としても表示されるようになった。
- stream-jsonでのネストされたサブエージェント転送に対応（`--forward-subagent-text`指定時、depth-2以降のサブエージェントの出力も表示される）。

**なぜ重要か:**
`strictAllowlist`はエージェントに社内ネットワークやCI環境で作業させる際の安全網として実務的で、MCPサーバーのエラー可視化は複数のMCPサーバーを組み合わせて運用する際のデバッグ効率に直結する。顧客環境にClaude Codeベースのエージェントを導入する立場では、こうした設定項目を把握しておくと安全性・信頼性の説明がしやすくなる。

**リンク:** https://code.claude.com/docs/en/changelog

## 3. Microsoft Agent Framework、Python版1.12.1を公開 — GPT-5.6キャッシュ制御・AG UIが正式stableに

**情報源:** [GitHub microsoft/agent-framework Releases](https://github.com/microsoft/agent-framework/releases)（python-1.12.1、2026年7月22日公開、直接WebFetchで確認）

**何が新しいか:**
Microsoft Agent FrameworkのPython版がv1.12.1に更新され、GPT-5.6向けの明示的なprompt cacheブレークポイント追加、AG UIパッケージのrelease candidateからstableへの昇格、カスタムMCP Streamable HTTPクライアント向けセキュリティガイダンスの追加、Gemini 3のthought signature保持修正が行われた。

**技術的なポイント:**
- `agent-framework-core`にGPT-5.6モデル向けの明示的なprompt cache breakpointを追加し、プロンプトキャッシュのヒット率をより細かく制御可能に。
- `agent-framework-ag-ui`パッケージがrelease candidateから正式stableへ昇格。
- カスタムでMCPのStreamable HTTPクライアントを実装する開発者向けに、セキュリティガイダンスが`agent-framework-core`に追加された。
- `agent-framework-gemini`で、function-callのリプレイをまたいでGemini 3のthought signature（内部推論トークン）を保持する修正が入り、マルチターンのツール呼び出しでの応答一貫性が改善。

**なぜ重要か:**
複数ベンダーのLLM（OpenAI・Gemini等）を1つのエージェントフレームワークで扱う際、各モデル固有の癖（プロンプトキャッシュの挙動やthought signatureの扱い）をフレームワーク側が吸収してくれるかどうかは実装コストに直結する。マルチベンダー構成のエージェント基盤を選定・構築する際の実務的な参考材料になる。

**リンク:** https://github.com/microsoft/agent-framework/releases
