# 毎朝ダイジェスト — 2026-07-29

**今日のひとこと**: MCP(Model Context Protocol)がプロトコル発足以来最大級の仕様改訂を発表。ステートレス化・認可強化など、エージェント基盤を触るエンジニアは要チェックの一日。Metaの新design system「Astryx」がMCPサーバーを内蔵して"AIエージェントが読めるUIコンポーネント"を打ち出し、研究側では長時間タスクに挑むエージェントの弱さを定量化するベンチマークが出た。

## 1. MCP、発足以来最大の仕様改訂「2026-07-28」を発表

- **情報源・日付**: [Model Context Protocol公式ブログ](https://blog.modelcontextprotocol.io/posts/2026-07-28/)、2026年7月28日／関連: [TechCrunch](https://techcrunch.com/2026/07/20/ais-most-important-protocol-is-getting-a-little-bit-easier-to-use/)、[VentureBeat](https://venturebeat.com/infrastructure/mcp-just-got-its-biggest-update-ever-heres-what-changes-for-ai-agents)、[InfoQ](https://www.infoq.com/news/2026/07/mcp-ema-enterprise-auth/)

**何が新しいか**: MCPの中核プロトコルが、双方向ステートフル方式から要求/応答型のステートレス方式へ転換。TypeScript/Python/Go/C#のTier 1 SDKが同時更新された。公式ブログは「認可の追加以来、最も大きな仕様変更」と表現している。

**技術的なポイント**:
- **ステートレス化**: `initialize`/`initialized`の交換と`Mcp-Session-Id`ヘッダーが廃止され、任意のリクエストがロードバランサ配下のどのインスタンスにも到達可能に。
- **Multi Round-Trip Requests (MRTR)**: サーバー側からのユーザー確認・パラメータ要求を、ストリームを張りっぱなしにせずステートレスに実現。
- **ヘッダーベースルーティング**: `Mcp-Method`/`Mcp-Name`ヘッダーで、ゲートウェイがJSONボディをパースせずルーティング・認可判定できるように。
- **キャッシュ拡張**: リスト応答に`ttlMs`と`cacheScope`を追加。
- **認可強化**: RFC 9207準拠の発行者検証、Client ID Metadata Documents (CIMD) への移行。Enterprise-Managed Authorization拡張が正式版に昇格し、IdP経由の集中アクセス制御が可能に。
- **拡張フレームワーク**: 長時間実行タスクを扱う「Tasks」機能がコア仕様から正式extensionへ移動。
- Roots/Sampling/Logging等の非推奨機能は最低12ヶ月の移行期間あり、旧クライアントとの非互換は自己申告されている。

**なぜ重要か**: MCPサーバー/クライアントを実装・運用しているなら、ロードバランサ構成やセッション管理コードの見直しが必要になる可能性が高い。FDE的にエージェント基盤を顧客に導入する立場では、この「ステートレス化」と「エンタープライズ認可」がまさに大規模組織導入の障壁を下げる部分であり、提案・設計に直結する。

リンク: https://blog.modelcontextprotocol.io/posts/2026-07-28/

## 2. Meta、AIエージェント対応のReactデザインシステム「Astryx」をOSS公開

- **情報源・日付**: [MarkTechPost](https://www.marktechpost.com/2026/07/21/meta-open-sources-astryx-an-agent-ready-react-design-system-with-150-accessible-components-seven-themes-and-a-cli/)、[GitHub: facebook/astryx](https://github.com/facebook/astryx)、初出2026年6月28日・7月にGitHub Trending再浮上

**何が新しいか**: Metaが社内で8年間かけて磨いてきたReactデザインシステムをMITライセンスでOSS化。150以上のアクセシブルなTypeScriptコンポーネント、7種類の既製テーマを提供し、Facebook/Instagram/Threadsなど社内13,000以上のアプリで使われてきたもの。GitHubで11,000スター超を獲得（本人確認済み）。

**技術的なポイント**:
- React + StyleX（Metaのコンパイル時CSSエンジン）ベースで、プリビルドCSSを同梱するためビルドプラグイン不要。
- CLIがすべてのコマンド・引数・フラグ・戻り値型を機械可読なJSON manifestとして公開し、AIコーディングエージェントが構造化された仕様を参照できる。
- MCPサーバーを内蔵しており、Cursor・Claude Code・GitHub Copilotなど MCP対応環境からプロジェクトのスキャフォールディング、コンポーネント一覧取得、テーマ生成、ドキュメント取得を共通インターフェースで実行可能（GitHubリポジトリ上でも「MCP Registry」への言及を確認）。
- Tailwind、CSS Modules、素のCSSでの上書きにも対応。

**なぜ重要か**: 「AIエージェントがUIコードを生成する際にハルシネーションを起こしにくい」ことを狙った設計であり、フロントエンド×エージェントの実務パターンとして参考になる。自社プロダクトにMCPサーバーを組み込む際の実装例としても具体的で、FDE的にクライアントのUIコード生成基盤を提案する際の引き出しになる。

リンク: https://github.com/facebook/astryx

## 3. 論文: Long-Horizon-Terminal-Bench — 長時間ターミナルタスクでエージェントは息切れする

- **情報源・日付**: [arXiv:2607.08964](https://arxiv.org/abs/2607.08964)（2026年7月9〜13日投稿）、[GitHubリポジトリ](https://github.com/zli12321/LHTB)、[Hugging Face Datasets](https://huggingface.co/datasets/IntelligenceLab/Long-Horizon-Terminal-Bench)、[プロジェクトページ](https://zli12321.github.io/LHTB/)

**何が新しいか**: 実験再現・ソフトウェア工学・マルチモーダル分析・対話型ゲーム・科学計算など9カテゴリ・46タスクからなる、既存のターミナルベンチマーク（Terminal-Bench 2など）より一桁重い長時間タスクのベンチマークを提案。最終結果だけでなく細分化されたサブタスクごとに部分点を与える「密な報酬」設計が特徴。

**技術的なポイント**:
- 各タスクはTerminal-Bench形式（参照解またはシミュレーションエンジン付き）をベースに、細粒度の採点可能なサブタスクへ分解。
- 評価されたエージェントは平均で1タスクあたり**約990万トークン**を消費し、**約231エピソード**、**約85.3分**の実行時間を要した。
- 最も性能の高かったモデルでも、部分点閾値0.95で**pass@1が15.2%**、完全達成（閾値1.0）では**10.9%**にとどまった。

**なぜ重要か**: 「長時間・多段階の自律タスク」がまさに現行の最先端モデルでも実用に耐えるレベルにない、という定量的な裏付け。自律エージェントの導入提案をする際に、どこまでを人間のチェックポイントに残すべきかの判断材料になる具体的な数値として使える。

リンク: https://arxiv.org/abs/2607.08964
