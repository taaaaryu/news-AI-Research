## 1. MCP仕様 2026-07-28 が確定 — 「プロトコル史上最大の改訂」、ステートレス化と拡張フレームワークへ

- **情報源・日付**: [Model Context Protocol公式ブログ「The 2026-07-28 MCP Specification Release Candidate」](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)（リリース候補公開: 2026年5月21日／最終版確定: 2026年7月28日）、関連: [VentureBeat](https://venturebeat.com/infrastructure/mcp-just-got-its-biggest-update-ever-heres-what-changes-for-ai-agents)、[SiliconANGLE](https://siliconangle.com/2026/07/28/biggest-ever-mcp-update-brings-metadata-cybersecurity-enhancements/)、[WorkOS](https://workos.com/blog/mcp-2026-spec-agent-authentication)

**何が新しいか**: MCP（Model Context Protocol）の新仕様2026-07-28が、5/21のリリース候補から約10週間のSDK・実装者による検証期間を経て7/28に確定した。プロトコルコアが「ステートレス」に転換され、従来必須だった`initialize`/`initialized`ハンドシェイクとセッション管理が廃止。プロトコルバージョンとクライアント情報は各リクエストの`_meta`に含める方式に変わった。

**技術的なポイント**:
- ステートレス化により、ラウンドロビン負荷分散でリクエストをルーティング可能になり、エンタープライズのAPIゲートウェイ配下でも動作しやすい設計に。
- 拡張フレームワークを正式化し、サーバーがHTML UIテンプレートをホストのサンドボックス内でレンダリングさせる「MCP Apps」、長時間実行タスク用の「Tasks」拡張（実験的コア機能から独立した拡張へ昇格）を導入。
- 認可まわりはOAuth 2.0／OpenID Connectとの整合性を6件のSEP（仕様強化提案）で強化（`iss`パラメータ検証の義務化など）、Entra・Oktaのような企業IDシステムとの連携を想定。
- Roots・Sampling・Loggingの3機能は正式な廃止ポリシー下で非推奨化（12ヶ月以上の移行猶予あり、当面は動作継続）。

**なぜ重要か**: MCPサーバー/クライアントを実装・運用する開発者にとって、セッション前提の実装は今後移行対象になる。AIエージェント基盤をクライアントに導入するFDE的な立場では、認可周りのエンタープライズID連携やステートレス化によるスケーラビリティ改善が、実導入の設計判断に直結する変更点。

リンク: https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/

## 2. Anthropic、Claude Mythos Previewが後量子暗号候補HAWKと縮小版AESに新たな攻撃を発見

- **情報源・日付**: [Anthropic公式研究ブログ「Discovering cryptographic weaknesses with Claude」](https://www.anthropic.com/research/discovering-cryptographic-weaknesses)、2026年7月28日／関連: [CyberScoop](https://cyberscoop.com/anthropic-claude-mythos-encryption-flaws-hawk-aes-pqc/)、[The Quantum Insider](https://thequantuminsider.com/2026/07/29/ai-finds-new-weaknesses-in-cryptographic-algorithms-anthropic-says/)、[TheNextWeb](https://thenextweb.com/news/anthropic-claude-mythos-cryptographic-attacks-hawk-aes)

**何が新しいか**: Anthropicは、Claude Mythos Preview（研究用モデル）が、NIST（米国標準技術研究所）が評価中の後量子暗号署名方式候補「HAWK」に対し、これまで使われていなかった数学的対称性を発見して鍵回復攻撃を高速化し、実質的な鍵強度を半減させたと発表。同時に、縮小版（7ラウンド）AESに対しても既存攻撃を200〜800倍高速化する新手法を示した。

**技術的なポイント**:
- HAWKは未実運用の候補方式だが、今回の攻撃により意図した安全性水準を保つには提案鍵サイズを倍にする必要があり、HAWKの効率面での優位性が損なわれると報告。
- AESへの攻撃は完全な10ラウンド版AES-128ではなく研究用の7ラウンド簡略版が対象で、実運用のAESへの直接的な脅威ではない。
- 数学ソフトウェア・既存研究・計算ツールにアクセス可能なマルチエージェント研究システムを用い、約60時間・API利用コスト約10万ドルで攻撃を開発したとされる。
- 研究成果とあわせて、AIの暗号解析能力を測定するための新ベンチマーク「CryptanalysisBench」（6種類の暗号プリミティブにまたがる191タスク）を公開。

**なぜ重要か**: フロンティアAIモデルが、人間の専門家によるレビューを何年もすり抜けてきた暗号アルゴリズムの数学的弱点を、マルチエージェント体制で自動発見できることを具体的な数値で示した事例。暗号・セキュリティが絡むシステムを扱うエンジニアにとっては、AIによる脆弱性発見が攻撃側・防御側双方の実務ツールになりつつある現状把握として重要。

リンク: https://www.anthropic.com/research/discovering-cryptographic-weaknesses

## 3. GitHub Models、本日7/30付で完全終了 — プレイグラウンド・推論API・BYOKも停止

- **情報源・日付**: [GitHub Changelog「GitHub Models is being fully retired on July 30, 2026」](https://github.blog/changelog/2026-07-01-github-models-is-being-fully-retired-on-july-30-2026/)、2026年7月1日公開（既存告知の確定版）／関連: [dev.to](https://dev.to/leobaniak/github-sets-july-30-as-the-hard-shutdown-for-github-models-cmc)

**何が新しいか**: 2026年6月に新規顧客向け提供を停止していたGitHub Modelsが、本日2026年7月30日をもって既存利用者も含め完全に終了した。プレイグラウンド、モデルカタログ、推論API、BYOK（Bring Your Own Key）のすべてが利用不可になり、関連UIも削除される。

**技術的なポイント**:
- 移行前の周知策として7/16・7/23に短時間の「ブラウンアウト」（意図的なサービス中断）を実施し、GitHub Models依存が隠れた本番依存になっていないかをチームに事前確認させる運用が取られた。
- GitHub Copilot関連でも、Gemini 2.5 ProとGemini 3 Flashが7/31付で全Copilot体験から非推奨化されるなど、Copilotのモデルラインナップ整理が同時並行で進んでいる。

**なぜ重要か**: GitHub Models経由でプロトタイピングやCI内の軽量推論を組んでいた開発者は、今日以降そのパスが完全に断たれる。Azure AI Foundryなど代替の推論エンドポイントへの移行が済んでいない場合、本番のCI/CDパイプラインやデモ環境が今日から静かに壊れる可能性があり、実務上は最優先で確認すべき変更点。

リンク: https://github.blog/changelog/2026-07-01-github-models-is-being-fully-retired-on-july-30-2026/
